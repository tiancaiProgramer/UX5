# 配置与首次使用

## 配置执行 Agent

1. 打开 **AI 配置**中的执行 Agent 配置区域，添加一份配置。
2. 填写便于识别的名称、实际供应商、可用模型和 API Key/Token；接口地址采用服务商官方文档或界面的正确默认值。
3. 保存后选中这份执行配置。多个配置可保留，当前选中的配置才是任务使用的执行路由。
4. 若服务商要求充值或该模型未开通，需要在服务商账户处理；UX5 不提供 API 额度。

凭据通过本机加密存储。不要把 Key 写进提示词、项目文件或 GitHub Issue。

## 配置思考 AI / 前端

思考 AI 用于交流、分析与计划，执行 Agent 用于实际任务，两者分开配置。

- 使用 API 模式时，在对应配置区域保存供应商、模型和凭据。
- 使用 CLI 模式时，先按客户端自己的正常流程安装、登录，再让 UX5 检测。账户登录由本人完成。
- 使用外部前端时，按前端集成区域的引导配置；外部客户端的会话历史不会自动变成 UX5 的 Memory。

可先只配置自己当前需要的一种接入方式，跑通后再增加其他前端。

## 启动和检查后台

在 **设置 → 运行环境与维护 → 系统与运行环境** 点击“启动”。先关注：

| 状态 | 含义 |
| --- | --- |
| OpenCode | 本地执行服务是否运行 |
| 模型凭据代理 | 本机模型代理是否运行 |
| MCP | 本地工具协议与工具注册是否就绪 |
| Tunnel | 仅在配置了需要隧道的外部接入时使用，新装默认不启用 |

隧道未配置不等于必须先配隧道才能用所有本地功能。若启动失败，保留错误类别；不要连续反复点击或重新安装。

## 给一个测试工程授权

1. 建立一个独立测试工程，默认工作区下可使用 `C:\OpenCodeBridge\Sandbox\work\demo`，实际路径以本机设置为准。
2. 进入 **设置 → 项目授权**，填写 Project ID（例如 `demo`）、具体项目目录，以及所需读取/编辑范围。
3. 只有需要官方 Codex 原生工程执行时才勾选对应选项；先确认官方客户端可检测且已登录。
4. 亲自审核项目确认与正常 UAC，完成后再发起工程任务。

不要拿整个系统盘当测试工程。项目授权、模型配置和客户端登录是不同步骤，某一步完成不会自动代替其他步骤。

## 完成第一个任务

回到工作台/对话，选择相应项目，先做一个容易核对的小任务。例如先要求读取工程结构并说明，不修改文件；确认结果后再尝试一项小修改。

任务详情用于查看执行结果、错误及产物；Memory 按主题保存 UX5 自身维护的任务进度与结果。可选模块在“组件与模块”中按需开启，旧自研模块原生命令执行在本版仍禁用。

## 常见问题

- **网页打不开**：确认 UX5 主程序仍在运行，使用刚打开的本机页面，避免旧书签指向过期会话。
- **保存/维护提示令牌无效**：刷新当前安装版新打开的页面，再处理操作；不要反复提交旧页面。
- **模型不可用**：核对当前执行配置、模型权限、地址与供应商额度，不要把 API Key 发到 Issue。
- **安装提交但启动失败**：提交不等于运行健康。记录版本和完整错误类别，并注明新装还是旧版迁移。
- **找不到主程序**：`OpenCodeBridge.exe` 就是 UX5；GitHub 的 Source code ZIP 不是可执行发行包。
